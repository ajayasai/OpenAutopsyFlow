# Roadmap with measurable acceptance gates

The code does not contain placeholder buttons for these capabilities. They are future work, not delivered features.

## Gate 1 — Departmental validation and security

Document the intended users, jurisdiction and approved case lifecycle. Test every local template and export with qualified reviewers. Run an independent threat-model review, penetration test, dependency/image audit and live-browser TLS/cookie/proxy acceptance suite. Require audited backup/restore drills, incident response ownership and access review before real case entry.

## Gate 2 — Complete preservation and correction workflows

Add disclosed correction/withdrawal/relationship history for mistaken evidence links without destroying originals. Add complete intermediate draft narrative history and policy-controlled export of relevant system events, with redaction/disclosure controls. Add records retention, legal holds, approved destruction, migration tooling and independently stored audit checkpoints. Acceptance: round-trip reconstruction on long-lived synthetic cases, with no silent historical changes.

## Gate 3 — Institutional scale and identity

Introduce PostgreSQL, explicit migration tests, row/tenant authorization design, streaming encrypted object storage and bounded background PDF/export jobs. Add OIDC/SSO with policy enforcement, managed MFA enrollment, approval identity validation, disaster-recovery isolation and key rotation with old-version verification. Acceptance: adversarial cross-tenant tests, migration/rollback drills and concurrent-user capacity measurements.

## Gate 4 — Interoperability and rich examination capture

Develop jurisdiction-specific request/report adapters and lab/registry integrations against documented interfaces. Add a rights-cleared anatomical model, injury annotations, photo derivatives and optional authenticated links that remain traceable to originals. Validate Unicode/complex-script reports, keyboard/touch accessibility and mobile workflows. No automated medical conclusions or signature substitution.

## Gate 5 — Comparative evaluation

Use the protocol in COMPARISON.md. Publish tasks, preregistered endpoints where appropriate, anonymized results and limitations. Claim “better” only for measured dimensions and named, configured comparison systems. Publication of open source alone does not establish clinical safety, novelty or product superiority.
